The version on the Chrome Web Store and AnkiWeb is 1.0.2, which worked on one
question bank and was MIT-licensed. This release is everything since.

**Both packages must be installed together.** The extension calls add-on ops
that only exist in 1.3.0. A new extension against an old add-on degrades with a
message rather than failing silently, but you want the pair.

## Two more question banks

**UWorld** and **MedPark** join Coursology. They share UWorld question ids, so
the same AnKing tags match on all three.

Behind them is a real adapter layer: a new bank is a set of selectors and page
heuristics, never new privileges. The extension still runs only on the hosts in
the manifest, still talks only to `127.0.0.1`, and still sends nothing anywhere.

## Take a question back out of Missed Qs

Saving used to be a one-way door — a mis-click meant fixing tags by hand in
Anki's Browse window. Reopening the dialog on a saved question now offers
**Remove from Missed Qs**, which undoes whichever save happened: it untags the
card, moves it back to the deck it came from, and deletes the copy if you made
one. If you have since refiled the card yourself, your filing wins.

It never costs you notes. The *Missed Questions* field and the AnkiHub_Protect
tag guarding it are left untouched.

## Missed questions, organised

- **A chapter subdeck per question**, built from the card's own AnKing tags —
  organ systems on Step 1, rotations on Step 2 — so the pile stays studiable by
  topic. It reuses a subdeck you already have rather than creating a parallel
  one beside it.
- **Three ways to keep one, changeable at any time:** move the real card (keeps
  its history and AnKing updates), tag only, or make a copy.
- **A new deck inherits its options preset** from the deck the card came from,
  instead of silently landing on Default and changing your daily limits.
- **Your notes are protected.** Mnestic writes into *Missed Questions*, so it
  tags the note `AnkiHub_Protect::Missed_Questions` — otherwise a term of notes
  can vanish on a routine AnkiHub update.
- **Retest exactly what you missed:** the question ids by chapter, ready to
  paste into your qbank's own test builder, and a filtered deck to study them.

## Accuracy

- **The tag query matched the wrong questions in two directions.** It could pull
  in COMLEX ids, and it could never match a bare `::#UWorld::<id>` tag at all —
  1,896 Step 3 cards in one real collection were invisible to it.
- **The tracker now separates two signals:** the qbank's own counter says how
  many questions you did, our log says which ones and how they went. It credits
  blocks it never watched, and re-baselines instead of going negative when a
  qbank resets.
- **Guessed questions count as missed**, if you mark them.
- Card readiness, image prefetch, weak-area breakdowns and the results toolbar
  all had bugs that assumed Coursology's page shape.

## Setup and the add-on

- **A first-run checklist** in the popup: is Anki running, are you paired, do
  you have a Missed Qs deck — and it creates the deck for you.
- **A Tools → Mnestic Bridge menu** in Anki: your pairing code, a way to issue a
  new one, and a status/deck check.
- Six new ops the extension needed, and two for the undo.

## Safety

- **The add-on cannot delete your cards.** Its one delete operation exists to
  undo a *Make a copy* save and refuses any note that is not a copy Mnestic
  itself created: it must carry Mnestic's marker tag and must not be
  AnkiHub-managed.
- **Removing a tag is limited the same way** — only tags under `Mnestic::`, so
  nothing can strip `marked`, `leech`, an AnKing tag, or `AnkiHub_Protect`.
- Both limits live in the add-on rather than the extension that calls it,
  because the add-on is what a request actually reaches.
- Question ids are pinned to digits where Anki queries are built, deck names are
  escaped for search, and an unreadable id list can no longer send Anki an empty
  query — which selects the whole collection rather than nothing.
